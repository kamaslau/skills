# 规范化规则细则（normalize.mjs 行为说明）

本文件是 `scripts/normalize.mjs` 的行为规格说明，供排查「某处为什么没转换 / 为什么被转换」时查阅。
修改脚本行为前请先阅读本文，并同步更新 `scripts/selftest.mjs` 中的用例。

运行环境：**Node.js >= 22**（官网公示的仍受支持的最低 LTS；v20 及以下已 EOL），
ESM，零第三方依赖（`opencc-js` 为可选增强）。

版本下限由 `package.json` 的 `engines.node` 与脚本内 `checkRuntime()` 双重声明，
后者在版本不足时报错退出（码 2）。因此可用到 v22.0.0 就存在的特性：
`node:util` `parseArgs`、`import.meta.dirname/filename`、`toSorted`、`replaceAll`、
`Object.hasOwn`、生成器与迭代器辅助。**不可用** `parseArgs` 的 `allowNegative`
（v22.4.0 才引入）——`--no-*` 开关一律以显式键名声明。

## 1. 数字

| 输入 | 输出 | 说明 |
| --- | --- | --- |
| `０１２３４５６７８９` (U+FF10–FF19) | `0123456789` | 无条件转换（受保护区域除外） |
| 半角数字 | 不变 | — |
| `ＡＢＣａｂｃ` (U+FF21–FF3A / FF41–FF5A) | `ABCabc` | 无条件转换（受保护区域除外） |

全角字母属于**中文语境信号**：判定标点上下文时按原字符计入 CJK，
因此 `見附錄Ａ.` → `見附錄A。`（`--no-letters` 可关闭字母转换）。

## 2. 标点符号

### 2.1 默认映射（半角 → 全角）

| 半角 | 全角 | 半角 | 全角 |
| --- | --- | --- | --- |
| `,` | `，` | `(` `)` | `（）` |
| `;` | `；` | `[` `]` | `［］` |
| `:` | `：` | `{` `}` | `｛｝` |
| `!` | `！` | `<` `>` | `＜＞` |
| `?` | `？` | `~` | `～` |
| `.` | `。` | `\|` | `｜` |
| `"` | `＂` | `'` | `＇` |

`--quotes curly` 时引号改输出 `“”` / `‘’`（按行内左右交替配对）。
`--symbols` 额外转换 `@ # $ % & * + = / \ ^ _ \`` → 对应全角形式；默认关闭，因为这些符号常与代码、变量、标签耦合。

### 2.2 转换前提：中文上下文

除句点外，标点仅在**左侧或右侧紧邻的非空白字符属于 CJK 范围**时才转换。CJK 范围含汉字、假名、谚文、中日韩标点与全角字符（U+FF01–U+FFEF）。

- `这是一个测试,继续` → `这是一个测试，继续` ✅
- `This is a test, isn't it?` → 原样 ✅（左右均无中文）
- `iPhone (苹果)` → `iPhone （苹果）` ✅（右侧为中文）
- `(see above)` → 原样 ✅

判定左侧时使用的是「已处理视图」：本行内已被转成全角的括号/引号会作为中文上下文参与判定，因此
`這場會議(含外賓)結束了.` → `这场会议（含外宾）结束了。`。

### 2.3 句点 `.` 的专门规则（最易出错，逐条核对）

按顺序判定，命中即返回：

1. `--period keep` → 不转换。
2. 左右均为数字 → 保留（`3.14` 小数点）。
3. 左右均为 ASCII 字母/数字 → 保留（`node.js`、`v1.2`、`index.html`、`U.S`）。
4. 句点位于词尾（右侧为空或空格）且尾部词命中缩写表 → 保留（`etc.`、`e.g.`、`Fig.`、`U.S.`、`J.` 单字母缩写）。
5. 左侧是 CJK → 转 `。`（`--period fullwidth` 时转 `．`）。
6. 左侧是 ASCII 字母/数字、右侧为空或空格，且**同向前 16 字符内出现 CJK** → 转 `。`（`参见图 2.` → `参见图 2。`）。
7. 其余 → 保留半角。

缩写表见脚本内 `ABBREVS`（etc / e.g. / i.e. / vs. / Fig. / No. / vol. / pp. / U.S. / a.m. 等）。

### 2.4 其他豁免

| 情形 | 示例 | 结果 |
| --- | --- | --- |
| 千分位逗号 | `1,000,000` | 保留半角 `,` |
| 时间/比分冒号 | `10:30` | 保留半角 `:` |
| 数字间波浪号 | `1~5` | 转 `～`（虽为数字仍转换，符合中文区间写法） |
| 运算符 | `!=` `?:` `->` `=>` `<=` `<tag>` | 保留半角 |
| Markdown 表格竖线 | `\| a \| b \|` | 整行保护，保留半角 |
| 撇号 | `don't` | 保留半角 |

## 3. 冗余空字符（`--whitespace blank|full|off`，默认 blank）

仅在**受保护区域之外**执行；代码块内的换行一律保留。

| 规则 | 示例 | 结果 |
| --- | --- | --- |
| 连续 3+ 换行 → 2 换行 | `甲\n\n\n\n乙` | `甲\n\n乙` |
| 空白行（仅含空格/制表/全角空格）清空 | `甲\n   \n乙` | `甲\n\n乙` |
| 片段紧接在前一个换行之后时，开头换行只留 1 个 | `---\n` + `\n\n\n正文` | `---\n\n正文` |
| 文首空行删除 | `\n\n正文` | `正文` |
| 文末连续换行收敛为一个 | `正文\n\n\n` | `正文\n` |
| （仅 `full`）行尾空白删除 | `正文   \n结束` | `正文\n结束` |

`blank` 刻意**不动行尾空格**：Markdown 用行尾两空格表示硬换行，删除会改变渲染结果。
`full` 才删，且同时处理全角空格 `　`。

## 4. 悬空标点（`--no-dangling` 关闭）

把**连续的全角标点串**收敛为其中强度最高者。强度表（`PUNCT_STRENGTH`）：

```
、 1  <  ， 2  <  ； 3  <  ： 4  <  。 5  <  ！ 6  ＝  ？ 6
```

- 强度不同 → 只保留强度最高的字符：`，。` → `。`、`，；` → `；`、`。，` → `。`、`，、。` → `。`
- 整串强度相同 → 原样保留：`！！`、`？！` 不动（重复常为作者有意的强调）
- 只处理全角标点，英文的 `?!`、`...` 不受影响

## 5. 繁转简

- 后端：`--backend auto`（默认）在 `opencc-js` 可解析时调用它做词组级转换，否则用内置
  `data/TSCharacters.txt` + `data/TSPhrases.txt`（单字 + 词组最长匹配，等价于 OpenCC `t2s`）。
  `--backend builtin` / `--backend opencc` 可强制指定；实际使用的后端显示在 `--report` 的 `backend=` 字段。
- 受保护片段用私用区占位符遮蔽后再送入转换器，确保原文逐字还原，且相邻中文仍保留词组上下文。
- 若发现整词被替换（如术语被 OpenCC 改写），用 `--protect` 保护该词后重跑。

## 6. 保护区域（永不改动）

结构化区域：

- 围栏代码块（` ``` ` / `~~~`），含未闭合时到文末
- 行内代码 `` `...` ``
- URL（`http(s)://`、`ftp://`、`www.`）、邮箱
- Windows 绝对路径 `C:\...`、常见 POSIX 路径 `/usr/...`、`/home/...`
- HTML 标签与注释
- 行内/块级数学公式 `$...$`、`$$...$$`
- YAML frontmatter（默认保护，`--convert-frontmatter` 可关闭）

Markdown 结构（`--format md`，`.md/.markdown/.mdx` 自动识别）：

- 表格行（以 `|` 开头）与分隔行
- 水平线 `---` `***` `___`、setext 标题下划线 `===`
- 标题 `#`、列表 `- * + 1.`、引用 `>` 的**行首标记字符**（标记后的正文照常转换）
- 脚注引用 `[^1]`、`{: #id }` 属性块
- 链接/图片：**仅** `[`、`]` 与 `(url)` 受保护，`链接文字照常转换`

## 7. 日语 / 韩语 / 朝鲜语人名保护

三层判定，命中任一即整体跳过繁转简：

1. **名单子串匹配**：`data/names_ja_ko.txt` 中的全名在文本中做 `str.find` 子串命中（可命中长句中的人名），外加 `--protect` / `--protect-name` / `--protect-file` 传入的名单。
2. **假名/谚文紧邻**：连续汉字片段的左或右紧邻字符为假名（含 `々〆ヶヵ`）或谚文时保护该片段，例如 `宮崎駿の新作` 中的 `宮崎駿`。
3. **日文/韩文独有字形窗口**：片段内出现 `辺 沢 辻 桜 気 発 県 駅 価 仏 円 恵 実 転 広 単 戦 図 続 読 働 専 楽 対 々 〆 ヶ ヵ 畓 乭 巭` 等字形时，以该字为中心向两侧各扩最多 2 个汉字，遇 `STOP_HAN` 高频虚词（的 了 是 在 和 與 會 這 那 場 …）停止，避免把整句判成人名。

局限与对策：无空格的长句中，冷僻日韩人名可能被判为普通中文而转简。对策是通读文本后用 `--protect` 显式列出；长期复用的人名追加进 `data/names_ja_ko.txt`。

## 8. I/O 约定

- **输入**：自动探测编码，支持 UTF-8 / UTF-16 / GB18030 / Big5 / EUC-KR / Shift_JIS；
  `--input-encoding` 可强制指定（取值在进入主流程前用 `new TextDecoder()` 校验）。
  探测实现见 `scripts/encoding.mjs`，原理见 `references/utf8-script-ranges.md` 第 5 节。
- **输出**：恒为 UTF-8；CRLF/LF 行尾原样保留；写文件时保证以单个换行结尾。
  BOM 由 `--bom keep|strip|add` 控制，默认 `keep`（沿用输入是否有 BOM）。
- **输出路径**：恒为 `.md`。`-o` 替换扩展名（`out.txt` → `out.md`）；`--suffix` 保留
  用户后缀再追加（`.norm` → `a.norm.md`）；文件输入默认写 `a.txt` → `a.md`、
  `a.md` → `a.normalized.md`；`--stdout` 强制只打印。
- 统计与 diff 输出到 stderr，转换结果输出到 stdout，两者可安全分离重定向。
- 批量处理多个文件必须显式指定 `--in-place` 或 `--suffix`，避免误写。
- stdin 用 `readSync` 循环读原始字节：既避免 `readFileSync(0)` 在部分平台只返回首个
  分片，也避免 `process.stdin` 异步迭代先按 UTF-8 解码而破坏非 UTF-8 字节。

### 执行顺序（硬约束）

`空白清理 → 数字/字母/标点 → 繁转简 → 悬空标点`

空白清理与悬空标点都会**改变文本长度**，而保护掩码是按索引标注的：

- 空白清理之后**重算掩码**（代码已处理）；
- 悬空标点**必须最后执行**，其后不再有依赖掩码的操作。

曾把悬空标点放在繁转简之前，掩码整体前移一位，导致「安倍晋三」的保护错落到
「倍晋三與」上（人名被转简、相邻字反而被保护）。改动顺序时务必回归
`['悬空标点后人名仍受保护']` 这条用例。

## 9. 回归测试

```bash
npm test                               # 内置字表 + opencc-js（若已安装）各跑一遍
node scripts/selftest.mjs              # 直接运行，输出 TAP
node scripts/selftest.mjs --only-builtin
node scripts/selftest.mjs --only-opencc
```

测试基于 `node:test` + `node:assert/strict`，按后端分组为 `describe`，每条用例一个
`test`。用例名附带该条改动的统计（数字/标点/字母/空白/悬空/繁简），便于对照。

两个后端都需全绿。新增规则时，先在 `CASES` 中补一条 `[名称, 输入, 期望输出, 额外选项]`；
改动 CLI 参数时同步更新 `describe('CLI 参数解析')` 中的断言。
